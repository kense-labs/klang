**2026 年 10 月 16 日的测试运行结果显示，K 的速度分别达到惯用 C++ 的 3.51x / 3.54x、专家级 C++ 的 1.24x / 1.26x，以及最佳安全 Rust 基准行的 1.13x / 1.19x**（分别对应 MSVC / clang 后端）。这些数据是全部十六项基准测试在大型数据规模下的几何平均值。峰值内存比率同样对 K 有利，分别为 1.95x、1.32x 和 1.25x。整个测试套件在全部三种规模下均已重新构建并重新运行，其中包括单独的 JIT 测量。

**本次更新中的源码改进在于无边界检查的图遍历。**
K 的两个图基准行均将顶点 ID 存储为 `u32 in dist`；CSR 还额外将前缀偏移量存储为 `u32 upto out`。校验在构造阶段完成，而 `checkfree fn bfs` 会验证遍历过程中不再保留任何边界检查。每个条目仍为 4 字节，且构造和校验阶段依然计入总耗时。
最新的大型规模 CSR 耗时为 699/617 ms，对比 C++ 为 784/761 ms、Rust 为 811 ms：领先同编译器下的 C++ 1.12x/1.23x，领先 Rust 1.16x/1.32x。在所有语言中，链式邻接表（linked adjacency）依然比 CSR 慢得多。在相同编译器下与原始 K 源码进行的交替对照试验测得，大型规模下链式邻接表的加速比为 1.21x/1.19x，CSR 为 1.08x/1.17x（`notes.md`）。这些数据衡量的是整个源码重写的整体效果；仅凭全套基准测试表本身，无法将单次源码改动与上一份报告以来的其他变化隔离开来。

**紧凑表示依然是最明显的优势。** `records` 比 Rust 快 2.02–2.26x，同时内存占用少 3.98x：可变模式枚举（variable-mode enum）按每条记录自身载荷的大小进行存储，其中包含内联文本。由于树结构中采用了同样的区分设计，`interp` 速度快 1.29–1.41x，内存少 2.04x。`sexp` 的内存占用比 Rust arena 少 2.43x，比 C++ 所有权节点（owning nodes）少 5.04x。对于 `strlist`，应将 K 的自有内联字符串与借用式的 `string_view`、扁平偏移量以及 `Vec<&str>` 行区分开来；它们具有不同的生命周期要求。

**落后与接近持平的情况依然存在。** `calc` 耗时为 481/491 ms，对比 Rust arena 为 436 ms。`lru` 耗时为 2,760/2,068 ms，对比 Rust 为 2,249 ms，因此在 MSVC 下落后、在 clang 下胜出。`scene` 为 460/371 ms，对比 Rust 为 379 ms，同样是在 MSVC 下落后、在 clang 下大致持平。本次更新仅对这些差异进行测量，并未重新验证早期关于究竟是哪一项具体编译器机制导致这些差异的诊断结论。

**无边界检查的核心计算（kernel）仍可能受限于后端优化。** 扁平索引版本的 blur 现已显式标记为 `checkfree`，耗时为 952/266 ms。行切片（row-slice）形式同样是 `checkfree` 的（包括切片构造在内），耗时为 298/269 ms。Rust 的两种形式均耗时 299–300 ms。因此，仅移除边界检查本身并不足以弥合 MSVC 在扁平索引核心计算上的差距。scene 的合成与递归更新也带有 `checkfree` 契约。在最快的粒子基准行中，K、Rust 与 clang C++ 几乎处于同一水平；在这种扁平数值计算负载上，微小差异并不足以作为语言优势的证据。

**分配方式与接口设计对对比结果至关重要。** `bintrees` 耗时为 206/204 ms，对比 C++ 的 arena 为 393/407 ms、Rust 的 arena 为 235 ms。逐节点分配的基准行耗时均超过三秒。在安全 Rust arena 行使用整数索引的地方，K 使用的是指向只增存储（growing storage）的类型化引用。在 `respond` 中，内联 K DTO 耗时为 507/491 ms，对比 Rust 的 DTO 为 1,338 ms；而 K 流式版本耗时为 454/400 ms，对比 Rust 流式版本为 540 ms。在决定哪项结果适用于特定应用时，应对比接口相匹配的实现。

**汇总指标结合了来自不同实现的结果。** 对于每种后端和对比层级，速度汇总均采用最快的 K 实现。内存数据则单独挑选，采用内存占用最低的实现。例如，`graph` 的速度取自 CSR，而其内存数据取自链式邻接表；`words` 的速度取自手写哈希表，而其内存数据取自 `dictionary`。`respond` 的头条指标使用的是流式版本；`blur` 在 MSVC 下采用行切片，在 clang 下采用扁平索引。没有任何单一实现同时具备所有这些最优结果。此外，`words` 对比的是不同的哈希函数与表策略：K 的字典比其手写表更省内存，但运行速度更慢。

**这些是在单台机器上测得的全进程数据。** 测量包含输入生成、数据结构构造与销毁，在两次预热后取三次运行的最佳值，且未绑定 CPU 核心。应谨慎看待微小差异，尤其是在对缓存敏感的图与 LRU 负载中。空进程基准下限（empty-process floor）目前在 K 上为 13.1 ms、C++ 上为 13.8 ms，而在 10 月 10 日的报告中约为 8 ms，同时 MSVC 版本也已从 19.51.36257 更新至 19.51.36260。跨日期的耗时变化不能完全归因于 K 编译器的改进。较早期的诊断研究仍保留在 `notes.md` 中并明确标注为历史记录；当前的对比结论均来自最新的结果表。
