# 一等异步函数与装饰器

K 实现了 `async fn`、结构化 `await` 挂起点、词法任务作用域，以及帧自有资源的清理机制。编译器负责检查所有权并将任务降级为 C 代码。该语言设计还包含带类型、可由用户自定义的 `@` 装饰器。

下面的语法展示了预期的表层写法。

<!-- fragment -->
```klang
@http::get("/health")
@trace("health")
async fn health(ctx: RequestContext&) -> Response {
    let status = await check_store(ctx.store);
    return response(status);
}
```

<a id="async-functions"></a>
## 异步函数

<a id="sequential-suspension"></a>
### 顺序挂起

调用会先求值实参并构造一个任务。当 `.join()` 消费该任务并驱动其运行至完成时，函数体才会开始执行。一个任务只有一个所有者，并且可以通过泛型 K 代码进行移动。在下面的协作式示例中，驱动器首先运行至 `await`，保存当前帧，然后在下一次轮询（poll）时恢复执行。

```klang
import std;

async fn calculate(x: i64) -> i64 {
    let saved: i64 = x * 2;
    let delta: i64 = await yield_now(3);
    return saved + delta;
}

fn main() {
    let task = calculate(7);
    print(task.join());
}
```

在挂起点处，异步函数体可以 `await` 一个子任务。它会取得该子任务的所有权，并在子任务处于挂起等待（pending）状态时保存自身的活跃状态。被 `await` 的值可以通过类型推断或绑定注解来确定类型。像 `await child();` 这样的语句会等待完成并丢弃任何结果。

```klang
import std;

async fn child(x: i64) -> i64 {
    await yield_now();
    return x * 2;
}

async fn parent(x: i64) -> i64 {
    let task = child(x);
    let value: i64 = await task;
    let extra = await child(3);
    return value + extra;
}

fn main() {
    print(parent(7).join());
}
```

当前实现接受带有类型化参数以及单个固定大小返回值或无返回值的顶层非泛型声明。`await` 可以出现在语句、值绑定、`return` 或 `break` 中。支持的表达式包括一元与二元运算、类型转换、字段读取、直接调用的实参、标量赋值，以及 `if`、`match` 和 `while` 的条件。整数 `for` 循环可以在任一边界处执行 `await`。它会一次性求值边界，并在循环体可能挂起时保存迭代状态。对具有无引用、固定大小元素的具名数组进行 `for` 遍历时，会保存计数器并在恢复时从当前区间读取下一个元素。这包括运行时确定大小的数组以及具名数组字段。对于局部存储或全局定长数组上的内联切片范围，边界同样只求值一次。循环会保存起始位置和计数，随后从同一所有者重建视图。经证明具有稳定所有者的已存储切片本身也可以被迭代，并且被重新绑定的切片会在下一次迭代时被读取。

具有可变大小元素的顺序数组会保存一个字节游标和元素索引。每次迭代在进入循环体之前，都会根据当前元素的编码大小推进游标。当隐式元素引用所属的所有者保持在稳定地址时，该引用可以跨越挂起保持活跃。该所有者内部的相对链接也依然可用。当已存储的切片改变其基址时，下一次迭代会沿新序列步进至保存的索引。普通迭代每步只需读取一个元素的大小。

表达式求值按从左到右的顺序进行。在 `combine(read_current(), await load(), read_current())` 中，第一次读取会在 `load` 开始前完成，第二次读取会在 `load` 结束后运行。任务帧会保存已求值的操作数，直到外围操作能够消费它们。短路运算符仅在右操作数被求值时才会挂起。部分求值的操作可以保存固定大小的数据，以及用于解析索引位置的受检切片描述符。如果后续实参发生挂起，已保存的持有者（holder）实参会保持对其底层槽位的借用。该借用（loan）源自帧中保存的引用或拷贝的持有者，因此重新绑定其原始变量不会解除该借用。

无引用的结构体、枚举和数组字面量可以在其初始化器中挂起。编译器会保存直至最后一个会挂起的初始化器之前已完成的初始化结果，然后构造该聚合类型。定长填充（fixed fill）只求值一次其填充值。新建的变长数组和可增长数组可以在被 `await` 的初始化器完成后再分配存储。构造过程中的取消操作会在赋值对外发布之前丢弃暂存的值。

对具名固定存储或具有已证明所有者的切片进行索引或赋值时，可以在计算索引或求值右侧表达式期间挂起。编译器会检查并保存每个已完成的索引。它会在索引求值运行之前保存已求值的切片，因此在求值期间重新绑定变量仍会保留原始目标位置。复合赋值也会在运行右侧表达式之前保存旧值。

返回时会先求值结果，然后运行该路径上已注册的 `defer`。从通过独立函数调用的回调中发起的非局部返回无法跨越轮询阶段。

每个可达的挂起点都为其后所需的值和 `defer` 保留了一份已保存状态。驱动器会为每个挂起点的已保存状态及子任务复用同一块存储。当所有路径都在某个挂起点之前返回时，检查器会跳过该续体及其已保存帧。

所有会挂起的函数体都使用受检类型和控制流活跃度分析（control-flow liveness）。当续体、后续循环迭代或当前取消路径上的 `defer` 可能读取某个局部变量时，该变量保持活跃。编译器会在求值完 `await` 操作数之后、挂起之前释放已死亡的临时存储。

活跃的局部引用或切片会使其所有经证明的所有者保持存活。较小的固定大小局部所有者保留在任务帧中。较大的固定大小所有者和运行时确定大小的所有者可以使用任务自有的数据栈。它们的地址在各次轮询之间保持稳定。稳定的全局存储和静态字面量也可以支撑已保存的借用。在后续实参中挂起的直接调用会保存已求值的引用或切片，并检查其原始所有者。即使变量在挂起期间被重新绑定，该调用仍会消费那个已保存的实参。

现有的借用规则会拒绝可能使活跃借用失效的同激活帧收缩（same-activation shrink）。异步挂起还会为活跃引用、切片、已采样迭代范围或顺序游标背后的已证明全局数组所有者建立租约（lease）。这涵盖只增数组和可增缩数组、容量受限数组以及嵌入在记录中的数组。租约在子任务运行或排空（drain）期间以及取消阶段的 `defer` 执行期间保持有效。追加操作会保留现有地址。遇到活跃租约的收缩或重叠替换会在变更位置报告运行时错误。

旧版 `reusable` 和 `reusable[]` 池也支持这些借用。活跃的局部池会将其元素和空闲链表都保留在任务自有存储中。已保存的池引用同时携带这两个区域。释放一个槽位或一段连续区域时其元素仍保持有效，因此已有的引用或切片在任务恢复后可以观察到因复用而写入的新值。

任务自有栈会在相关 `defer` 执行完毕后释放其区域。运行时在裁剪未使用内存页时会把停泊（parked）的栈包含在内。C 后端允许任务的初始状态、每个挂起点拷贝的 K 值以及返回值各自最多占用 4 KiB。

<a id="borrowed-task-inputs"></a>
### 借用任务输入

异步函数可以接受指向具有稳定元素布局数据的引用、可选引用或切片。当被链接的数据同样具有稳定布局时，它可以沿底层所有者内部的自相对链接（self-relative links）访问。带有借用输入的任务直接在 `await work(input)`、`work(input).join()` 或 `task_scope(work(input)) { ... }` 中构造。编译器会在每个实参求值时检查其所有者，并拒绝临时所有者或可能逃逸出该受检调用的任务值。

被 `await` 的子任务会使其调用者的借用存储保持存活，直到子任务完成或完成取消。从自相对链接解码得到的引用继承原始借用，包括当它指向已采样切片之外但仍处于同一所有者内部时。子任务可以将该引用转发给另一个受检任务。对借用全局数组的直接 join 也会租用该存储直到返回。词法任务作用域会从任务构造开始直至结束（包括取消清理期间）一直租用经证明的全局或局部所有者。每个任务的租约在驱动器将其分离（detach）时结束。作用域会在所有者存储超出作用域之前移除其租约记录。随着各任务轮流执行，可写输入可以更新已有元素。

当可增长数组或容量受限数组的元素具有稳定布局时，任务可以通过只读引用借用整个数组。该引用读取数组当前的长度，完整迭代可以访问在两次轮询之间追加的元素。切片只采样一次基址和范围，即使其源引用随后被重新绑定也是如此。共享借用会在任务仍可能读取数组时拒绝收缩或替换该数组。词法任务作用域会将该借用一直持有至取消清理完成。

按值传递的固定大小结构体或数组可以持有指向多个独立拥有区域的引用和切片。任务会在实参求值时拷贝这些引用和切片槽位。重新绑定原始值中的槽位不会影响该拷贝，而对现有元素的写入仍可通过拷贝的视图观察到。每个可能的底层所有者都会被单独检查，并在完成和取消期间保持存活。被 `await` 的子任务可以接收相同的拷贝视图，调用者也可以跨越挂起保留此类局部值。嵌套引用具有与直接借用相同的稳定布局要求。整个数组的调整大小（resize）权限通过顶层可写引用传递。

任务还可以接受指向固定大小持有者的 `const` 引用，该持有者包含稳定的引用和切片槽位。该持有者可以位于自有的局部或全局变长区域内的元素或字段中。对于局部存储，编译器会在所有实参求值完毕后检查其内容的所有者。被 `await` 的子任务会将该存储保持在稳定地址上。对于全局持有者，编译器会沿整个程序中的存储操作和调用进行追踪。只读引用字段可以指向另一个固定大小持有者。编译器会沿着这些链接追踪到底层区域，即使链接形成环，每个所有者也只访问一次。任务会在整个取消过程期间保持每个触及的持有者和每个底层所有者有效。在借用活跃期间，运行时会拒绝重新绑定槽位、为切片槽位赋值或替换包含这些槽位的值。标量字段以及槽位所指向的元素仍可按常规规则更新。一旦任务完成或排空取消，调用者即可重新绑定这些槽位。

当已位于可增长数组中的某个持有者被借用时，该数组仍可追加元素。受限数组可以保留指向已弹出元素的类型化引用。当所有进入受限数组的借用都可被采样时，运行时会保护数组头以及任务实际可触及的槽位。编译器会为持有者的布局生成遍历器（walker）。从已求值的任务输入、保留的局部变量或跨 `await` 保存的早期实参出发，运行时会遍历活跃的枚举变体、拷贝数组的活跃元素以及持有者之间的只读链接。对于每个根，它对每个地址和布局只访问一次（包括环状结构），然后合并范围用于写检查。没有间接借用的直接引用使用单个范围。调用者和子任务可以保护同一数组中的不同槽位。`push`、`append`、使用 `resize` 扩容以及赋值都可以写入互不相交的槽位。它们会拒绝跨越被借用槽位的写入——即使该槽位超出当前长度，或者已挂起的任务在取消清理时仍需要该槽位。数组头租约会阻止收缩数组。如果某个借用的范围无法被采样，编译器会保护该所有者的整个预留区域。

可写整数组输入可以在直接 `await`、`.join()` 或 `task_scope` 期间对独立拥有的局部数组进行扩容或收缩。该调用会作为对该所有者可能进行的 resize 进行检查。对于调用者保留的引用和切片，适用常规的数组视图规则。同一任务的其他输入以及同级任务的输入必须借用独立的存储。每个可写输入在任务体中都有自己的根，因此收缩操作也会检查任务自身创建的视图。容量受限数组保留其类型安全的复用语义。

在 `task_scope` 中，可写借用从构造函数完成时开始。当每条到达该访问的路径上都执行过 `join` 或 `cancel`，或在作用域退出排空了任务后，调用块即可再次访问该数组。对检查器而言，观测到 `finished` 并不会释放该借用。该规则同样适用于别名以及通过捕获变量访问的存储。运行时会在获取可写借用时检查是否存在重叠的活跃借用。可写任务可以通过直接 `await` 或 `.join()` 转发其输入，包括当子任务在取消清理期间调整其大小时。驱动器会在整个清理期间保持该可写借用，仅在任务结束后才将其分离。

租约使用任务帧或作用域存储按驱动线程进行追踪。可增长区域使用其数据栈标识。内联容量受限数组使用所有者的字节区间，因此通过外围记录进行的替换也会受到检查。帧记录可以同时携带两者。拷贝型替换会在求值传入值之后检查租约。带有自相对链接的固定布局替换会使用其最终地址来编码链接，因此它会在构造之前检查租约。其初始化器可以驱动使用独立存储的任务。检查器会拒绝可能使用正在构造区域的任务，包括通过别名使用该区域的情况。

根结构体的独立拥有字段各自保留自己的租约。借用一个字段不会影响兄弟区域的可变性。任务还会跨越挂起保持各个局部字段存活。按引用传递整个所有者会保持其描述符和各组件地址稳定。

<a id="cleanup-across-suspension"></a>
### 跨挂起清理

在任务体中获取的固定大小 `own` C 句柄可以移入挂起的帧中。在挂起点之前注册 `defer` 即可确保即使任务永不恢复，也能释放该句柄。`defer` 会在声明点预留其句柄，因此后续代码可以借用它，但不能独立释放或转移它。

在正常完成时，恢复后的函数体会在返回时运行其 `defer`，包括返回类型化错误值的情况。在挂起期间被取消时，驱动器会先排空活跃的子任务，然后按逆序运行该挂起点已注册的 `defer`。

`own` 参数会在构造时将其句柄移入任务中。当任务接受自有（owned）参数时，其连续的前导 `defer` 语句必须使用其输入和可访问的全局变量来释放所有这些参数。在首次轮询之前取消会按逆序运行这些 `defer`。一旦任务开始运行，它们就会并入函数体的其他 `defer` 中。对于没有自有输入的任务，在首次轮询之前取消不会执行函数体。

被携带的 `defer` 可以使用局部临时存储并释放其资源。检查器拒绝在这些回调中调整外部 K 缓冲区大小以及替换外部引用，因为作用域退出时可能会在返回值已经求值之后才运行它们。

<a id="lexical-task-scopes"></a>
### 词法任务作用域

`task_scope` 接管一组固定列表任务的所有权，并携带该作用域的控制器运行尾随代码块。驱动器会在轮到每个任务时启动它。该代码块可以步进推进队列、取消任务并等待其排空，或者 join 任务并使用其类型化结果。

```klang
import std;

async fn calculate(x: i64) -> i64 {
    await yield_now();
    return x * 2;
}

fn main() {
    task_scope(calculate(2), calculate(7)) { scope =>
        scope.step();
        scope.cancel(0);
        print(scope.join(1));
    }
}
```

`step()` 在不阻塞的情况下最多推进一个可运行任务，并返回作用域中是否仍有未完成的工作。`wait()` 推进一个可运行任务，如果所有任务都在停泊等待，则先等待通知。空作用域上的这两个操作都会立即返回 false。`wait_for(milliseconds)` 同样最多推进一个任务。在带有托管等待器（hosted waiter）时，如果所有任务都在等待，它最多可停泊等待所提供的 `i64` 毫秒数。零或负时长只检查而不停泊。在超时或唤醒后仍有未完成工作时它也可能返回，因此有截止时间的代码需要检查自身的单调时钟。`finished(index)` 检查基于 0 的常量索引处的任务是否已达到终态。该操作会保留该槽位供 `join` 或 `cancel` 使用。`join(index)` 和 `cancel(index)` 使用基于 0 的常量索引。任一操作都会消费该槽位。当某个操作正在等待目标任务时，其他任务可以继续运行。代码块可以返回结果，且控制器只能在拥有它的代码块内部使用。代码块退出时会取消并排空所有未完成的任务，包括从外围函数提前返回的情况。join、取消和作用域退出在排空时使用同一套等待路径。

<a id="task-model"></a>
### 任务模型

`async fn f(...) -> R` 声明异步函数体的返回值类型。调用会按源码顺序求值实参并构造一个任务。函数体在执行器推进该任务时开始执行。`await task` 会推进任务，并在任务处于待定状态时挂起外围异步函数体。完成后会将声明的结果交付给等待方函数体。通过普通函数调用发生的隐式挂起属于编译错误。

每个任务都针对其函数和特化版本拥有一个具体的、静态确定大小的帧类型。编译器知晓其结果类型和引用根。带有自有或拷贝输入的任务可以绑定到变量、通过参数或返回值移动，并由泛型代码组合。借用输入则采用上文所述的受检调用方式。显式任务类型语法仍处于开放状态。每个任务拥有一个所有者和一位消费者。词法任务作用域可以拥有多个任务，并在离开作用域前 join 或取消其拥有的任务。[一等函数提案](functions_and_typescript_runtime.md#first-class-function-values)将这些所有权规则扩展到了由闭包创建的任务。

任务帧保存跨越挂起保持活跃的固定大小值。已保存的引用、切片以及持有它们的拷贝值可以指向固定的局部变量、任务自有的数据栈，或由调用方保持存活的调用方存储。当前实现返回不含引用的固定大小值。自有的可变大小结果需要一个在完成期间始终保持存活的显式目标位置。

取消会从拥有者任务传播到其未完成的子任务。编译器为活跃挂起点生成清理代码，并按逆序执行一次待处理的 `defer` 体。待处理的清理体必须同步完成。终态转换只会记录一次完成或取消。从未启动的任务可以通过构造时建立的前导 `defer` 释放自有输入。所有权草案描述了更多的帧所有权规则。[协程帧](coroutines.md#45-rules-at-a-suspension-point) · [所有权与取消](ownership.md#53-design-b-own-frames-and-cancel)

语言本身定义了任务构造、挂起、结果交付与清理。标准库提供了用于测试的确定性执行器、用于 `async fn main()` 的入口驱动器，以及用于事件循环和 OS I/O 的适配器。执行器驱动编译器生成的状态转换。帧存储由所有者或执行器选择。[异步状态机与执行器](https://doc.rust-lang.org/stable/book/ch17-01-futures-and-syntax.html)

<a id="native-operation-tasks"></a>
### 原生操作任务

`native_task<T>(handle)` 消费一个带有单个 `u64` 字段的 `own` C 句柄记录，并生成一个可被 `await`、join 或移入词法任务作用域的任务。C 端使用带版本的 `k_foreign_task` 描述符以 `(uint64_t)(uintptr_t)descriptor` 的形式提供该句柄。描述符及其帧在整个过程直至 `finish` 完成之前一直保持存活，包括当任务在首次轮询前被取消的情况。

`T` 是最大不超过 4 KiB 的固定大小 C 兼容值。原生提供方（provider）提供与之匹配的 C 布局并在描述符中声明其大小。一次轮询可以在待定期间借用任务的结果槽位。就绪的轮询会写入结果，而终态轮询或成功排空则会结束该借用。请将可恢复错误保存在结果值中，以便 K 调用方对其进行分支处理。驱动器的错误状态负责处理驱动该操作本身的失败。

可选的 Cordis TCP 提供方通过该边界交付单个字节、EOF 或套接字错误。其原生任务会固定创建它的组件，直到 `finish` 返回。[可取消的 TCP 接收](cordis_microkernel.md#cancellable-tcp-receive)

<a id="deterministic-native-driver"></a>
### 确定性原生驱动器

`src/runtime/runtime_tasks.h` 提供了原生任务驱动器。发行版会将其安装到 `include/klang/runtime_tasks.h`。每个任务都拥有由调用方提供的稳定存储。作用域会借用其任务记录，直到它们达到终态。其有界队列每次推进一个任务，并在不进行分配的情况下轮转待定任务。提供方可以从回调中提交任务。试图步进同一作用域的回调会收到 `BUSY`。

驱动器调用 `poll` 来推进常规进度。终态的 `poll` 结果证明外部借用已经结束。取消请求在两次轮询之间生效。对于待定任务，驱动器会发送一次 `request_cancel` 通知，然后持续调用 `drain` 直到提供方确认完成。在此期间，任务保留其队列槽位及所有帧资源。`finish` 回调在终态转换时运行一次。其 `started` 参数使帧能够区分函数体内注册的清理与构造时已拥有的资源。关闭（shutdown）会停止接受新提交。调用方会持续驱动待处理的取消操作，直到作用域为空。

<a id="hosted-readiness"></a>
### 托管就绪机制

托管驱动器在首次注册具备就绪感知能力（readiness-aware）的任务时会分配一个等待事件。提供方可以返回现有外部任务描述符的可选扩展 `k_foreign_task_ready`。在未完成的 `poll` 或 `drain` 之后，其 `arm` 回调会在用于发布完成状态的同一同步保护下检查就绪状态并拷贝提供的唤醒器（waker）。如果操作已经取得进展，回调返回 false 且任务保持可运行状态。所提供的唤醒器中的空信号（null signal）用于在驱动器分配事件之前探测就绪状态。

`k_task_wake` 可以在提供方的工作线程上运行。事件会锁存该信号直到作用域将其消费，包括当信号在检查完可运行队列之后、宿主睡眠之前到达的情况。只有驱动线程会执行 `poll` 和 `drain` 回调。通知允许作用域中停泊的任务重新检查就绪状态。正在 `await` 的父任务会将其唤醒器转发给子任务。协作式任务以及使用原始描述符的提供方继续通过非阻塞轮询路径运行。

原生宿主可以在驱动线程上获取一个唤醒器并将其交给另一个所有者，以通过 `k_task_request_shutdown` 请求关闭。驱动线程会在两次回调之间应用该请求，并继续等待任何待处理的排空过程。提供方在从 `finish` 返回之前会静默其信号发送器。宿主会在作用域为空且外部所有者停止发送信号后释放该事件。原始 C 驱动器也支持调用方自备的事件操作或手动步进。

C、K 互操作以及 Cordis 夹具均使用该驱动器。编译后的父任务存储其子任务帧并在每次轮询时推进它一次。父任务取消会请求子任务取消，父任务排空则会等待直到子任务进入终态。原生生命周期测试会在子任务排空期间持有一个外部借用，并同时推进父任务作用域中的另一个任务。编译器会为活跃的 `defer` 生成终态回调。K/C 互操作夹具验证了句柄跨挂起的存活情况，以及在完成与取消时严格仅释放一次的行为。[任务生命周期测试](../testing.md#configurations-and-backends)

<a id="decorators"></a>
## 装饰器

元数据声明可以使用 `decorator Route(provider: const u8[:], capacity: u32) on async fn(i64) -> i64;` 指定精确的处理程序契约。K 会在函数声明处解析 `@Route(...)`，并将配置实参折叠为一条类型化记录。代码可以通过 `decorator_metadata<Route>(handler)` 读取该记录。Cordis 流夹具将该记录传递给常规的提供方选择和读取器设置流程，从而验证与显式配置完全一致的激活、响应与退役行为。[类型化元数据装饰器](../reference.md#typed-metadata-decorators)

包可以在其某个命名空间中定义带有类型化参数及受支持声明目标的装饰器。其他模块可以导入该装饰器，并使用 `@name` 或 `@package::name(argument)` 加以应用。编译器会在声明处解析装饰器，检查其目标和参数类型，并在编译期求值其配置参数。

同步包装器使用静态绑定的 `next()` 调用。编译器会通过常规调用检查器转发特化后的具体参数、泛型绑定和函数值。在检查包装器返回值之前，它会先从原始函数体获取推断结果。引用检查与所有权检查贯穿全程。C 句柄夹具观察到在正常退出和异常退出时，均会在包装器清理之前触发一次释放。[同步装饰器包装器](../reference.md#synchronous-decorator-wrappers)

异步包装器会编译为受检的任务阶段。每一层随着调度器轮询而运行，并可以通过 `await next()` 将其原始输入转移给子任务。编译器会检查续体在每条执行路径上最多被消费一次。在子任务启动之前，该层保留原始输入的清理责任；一旦子任务启动，则由子任务拥有这些输入的取消与清理权。父层在运行其活跃的 `defer` 之前会等待子任务排空。[异步装饰器包装器](../reference.md#asynchronous-decorator-wrappers)

配置实参按从上到下的顺序处理。包装器则从最底层的装饰器向上组合。执行首先进入最外层包装器，随后随着每次续体运行依次进入后续包装器。这遵循了 TypeScript 所采用的组合顺序。[TypeScript 装饰器](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-0.html#decorators)

结构体、枚举及其具名字段会在标称声明（nominal declaration）上携带元数据。类型别名和泛型实例化都会解析到该声明，而枚举载荷字段同时还具有变体标识。消费者无需构造值即可查询该常量记录。编译器会将这些记录排除在被注解值的内存布局之外。`decorated` 展开源为库提供了显式命名空间或字段所有者内的声明及类型化元数据。函数绑定保留重载标识。Cordis 通过该路径发现处理程序的注册记录，并将其用于常规的提供方选择和读取器设置。[枚举被装饰的声明](../reference.md#enumerating-decorated-declarations)

<a id="implementation-and-acceptance"></a>
## 实现与验收

1. 原生测试与 TinyCC 测试覆盖延迟执行、类型化结果、多个顺序 `await`、子帧复用，以及针对本会跨越挂起点的引用所给出的诊断。
2. 任务作用域测试检查首次轮询前以及每个顺序挂起点处的取消行为。C 所有权夹具与 Cordis TCP 夹具验证清理仅运行一次，且待定的外部操作会先完成排空。提前返回测试检查多个阶段下的结果与清理顺序，包括在词法任务作用域仍拥有一个待定子任务时返回的情况。结构化任务测试检查分支绕过、挂起的 `match` 分支中的载荷、直接 `return await` 与 `break await`、定长数组迭代，以及在不同迭代轮次上的取消。活跃度测试涵盖已死亡的临时存储、跨循环回边使用的值，以及取消期间由 `defer` 函数读取的局部变量。在一个从 `i64[256]` 和 `u8[512]` 计算 `await` 操作数的分支中，当两个数组在挂起处均变为死亡状态后，在 macOS arm64 上通过 Clang `sizeof` 测得的完整生成的 C 任务帧大小从 2,620 字节降至 32 字节。表达式测试检查跨多个挂起点的实参求值顺序、按值聚合拷贝、复合赋值、短路求值、仅求值一次的边界，以及任何后续操作数运行前的取消行为。构造与位置测试检查嵌套数组和枚举字面量、延迟分配、发布前的取消，以及源变量在任务挂起期间发生改变的多级索引。迭代测试涵盖轮询之间的增长、按任务划分的数组所有权、边界只采样一次的内联切片范围，以及在多个任务保持数组存活时的内存裁剪。借用测试涵盖调用返回的切片、替代所有者、重新绑定被索引的接收者、取消以及收缩诊断。顺序遍历测试涵盖可变大小字符串、定长字段变更、增长、自相对链接以及切片重绑定后的取消。
3. 元数据声明、`@` 应用与类型化获取覆盖命名空间导入、重载选择以及签名诊断。同步包装器测试了堆叠执行、泛型与推断签名、多返回值、引用返回，以及经由正常和异常退出的所有权转移。
4. 异步包装器测试了推断的完成类型、任务借用，以及启动续体前后的取消行为。C 句柄夹具检查了这些取消阶段以及包装器提前返回时严格仅释放一次的行为。Cordis 流夹具在待定的原生 TCP 读取期间取消了一个带装饰器的处理程序，并检查了排空后的套接字关闭。两个夹具均通过 TinyCC 和原生 C 运行。
5. 声明元数据测试覆盖别名、泛型特化、根结构体以及独立的枚举变体字段。原生测试与 TinyCC 测试将物理布局与等效的无装饰记录进行了对比。语言服务器将字段选择器解析到其声明。
6. 作用域枚举测试覆盖重载标识、导入作用域、泛型类型、初始化器中的字段访问器以及空 `match` 片段。异步夹具 `await` 所选中的处理程序，Cordis 夹具则将发现结果与显式注册进行了对比。
