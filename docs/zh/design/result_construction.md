# 通过函数结果构造

包含相对引用的新构造值可以由具名函数和尾随块（trailing block）返回，由控制流选择，并通过其他调用转发。指向现有元素的引用必须在接收槽位（receiving slot）处进行编码，而该槽位所属的根（root）也必须包含该元素。

这是一种通用的构造行为。它不需要池类型、内建分配器、字段私有性特性，也不需要在构建函数（builder function）上添加注解。

<a id="checker-model"></a>
## 检查器模型

有三项事实保持相互独立：

* 结果的类型，由其生成方推断或声明。尾随块仍然自行推断其类型；裸 `[]` 不会获得上下文推断的元素类型。
* 值究竟是新构造的，还是现有存储的拷贝。块尾部以及每条被选中的值路径都遵循现有的拷贝规则。
* 接收存储位置。实参、操作数临时量以及被丢弃的表达式各自拥有自己的存储位置，绝不会借用外层结果的目标位置。

具名返回拥有一个符号化的接收方（symbolic receiver）。相对初始化器会添加约束条件，将该接收方与包含其目标的根关联起来。调用会将这些根通过其实参进行映射，并对照实际接收方检查这些约束条件。转发式返回会将约束条件继续传递给它自己的调用方。当接收数组是高阶函数的参数时，尾随块中捕获的根也会使用同样的机制。

检查器会将这些约束条件记录在函数的摘要中，并在每次调用时加以验证——包括已缓存的特化版本、分派分支（dispatch case）以及递归轮次。它不会仅凭第一个调用方就推断出某种保证。生命周期随返回时的活动记录（activation）一并结束的局部根，无法满足结果约束条件。非局部返回（nonlocal return）会通过每一个中间调用，将约束条件映射到其实际目标上。

参数类（parameter class）内部已有的证明仍然局限在该次活动记录内：即使某个实参精确的外层根未知，它仍然可以链接通过同一参数访问到的两个元素。

<a id="emission"></a>
## 代码生成

包含相对引用的定长聚合类型结果无论大小，均使用带类型的输出指针。接收栈槽会提供其最终地址。普通返回、多结果转发、分支分派（case dispatch）、内联块以及非局部返回都会直接使用该地址。普通定长结果的 ABI 保持不变，并且无需优化器即可实现正确的放置位置。

只要表示形式转换保留了链接所在的区域，它们就会保留自包含的 `self` 和空链接（null link）。如果一个结果依赖其接收方的根，适配器就不能暂存或重定位它的字节。该结果可以使用相同的表示形式，或者直接在 ADT 标签之后构造变体。它不能被用作调整大小（resize）时的填充值，因为该操作只构造一次值并将其拷贝到多个槽位。

现有的增长、收缩、生命周期与部分构造规则依然有效。回调在构造位置执行一次。push 操作仅在元素构造完成后才会暴露其新的长度。

<a id="validation-and-integration"></a>
## 验证与集成

回归测试夹具涵盖定长与变长聚合类型、`map`、具名返回与推断返回、转发回调、带值 `break`、多返回值、分支分派（case dispatch）、递归、相对于池的 `self` 以及非局部返回。拒绝（报错）测试夹具涵盖现有存储的拷贝、后续调用中的错误根、已缓存的回调、局部临时量与操作数临时量、实参隔离、被丢弃的结果、冲突的增长操作、调整大小填充（resize fill）以及布局转换。原生 C 与 TinyCC 运行均在启用运行时检查的情况下测试 `-O0` 和 `-O2`。

这些编译器改动在池分支变基（rebase）之前已独立合入 master。`slot_pool.alloc_with` 使用普通的库级控制流：将构建函数的结果赋值到回收的槽位中，或者将其压入新的槽位中。它不需要额外的编译器特权。
