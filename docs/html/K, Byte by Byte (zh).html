一门内存安全的系统编程语言——无堆、无垃圾回收、无生命周期标注。

每个可增长的值都位于少数几个数据栈之一中，数据栈的数量在编译时即可确定。每个栈最多同时容纳一个处于增长中的值，且始终位于栈顶，因此增长只需移动一次指针，绝不会搬迁任何已有数据。离开作用域时，只需一次写入即可释放该作用域构建的全部内容。

数组按其大小的行为方式来选择

教程 §5

K 中没有单一的数组类型。除切片外，下面每一种数组都是“元数据紧跟元素”，内联且紧凑排列，没有指向独立内存块的指针。切片则是对其中任意一种的视图。

T[k]定长数组编译期确定大小。完全没有元数据。C T[k] · std::array · Rust [T; N]
T[]冻结数组构建时确定大小，之后长度永不改变。Rust Box<[T]>，但内联存储
T[varint]紧凑冻结数组与前者相同，但长度只占 1 或 2 字节。无标准等价物
T[..k]有限容量数组在 k 个槽位内增减，内联保存在宿主中。Boost static_vector · Rust ArrayVec
T[..]构建期定容数组在创建该值时确定最大容量。无标准等价物
T[>..]只增不减数组主力数组类型。增长时指向其中的引用依然有效。std::vector · Rust Vec，但不会重分配
T[>..<]可增可减数组用于栈、队列和堆等结构。std::vector · 用作栈的 Rust Vec
T[:]切片对上述任一类型的视图，不会产生任何拷贝。std::span · Rust &[T]

每个卡片最后一行列出了 C、C++ 或 Rust 中最接近的等价类型。

字符串就是 u8 数组。u8[>..] 用于构建字符串，u8[] 存储成品字符串，u8[..16] 把短字符串直接嵌进结构体，u8[:] 则用于查看他人持有的字节序列。

嵌套数据保持内联

教程 §8

包含字符串和列表的记录本身就是一段连续字节。下面这笔订单含有一个客户名和两条明细项，编译器将其排布在 29 字节中，零指针、零堆分配。

book.push(Order { id: 1001, customer: "alice",

引用始终有效，且由编译器证明

教程 §4

增长永不移动已有数据

var items: Item[>..] = [];
let first .= items.push(Item { 1, 0.5 });       // 指向第 0 个元素的引用
for i: i32 in 2..1000001 { items.push(Item { i, 0.0 }); }
first.weight = 99.5;                            // 依然有效
print(items.len, " items, first is ", items[0]);
1000000 items, first is Item { 1, 99.5 }

push 会返回指向新元素的引用。vector 或 Vec 在增长时可能会重新分配内存，因此 C++ 和 Rust 无法做出这种保证。仓库中各基准测试的 Rust 版本都只能改用整数索引。

C++
一旦 push_back 触发重分配，指向 vector 内部的引用就会悬垂，属于未定义行为。想安全保留引用，必须提前 reserve() 或改用 deque。
Rust
借用检查器会拒绝在 v.push() 期间持有 &v[0]（错误 E0502），因此代码只能改存索引。

无需标注的安全性

struct Node { v: i64, left: Node? }

fn main() {
    var root = Node { v: 1, .. };
    {
        var child = Node { v: 2, .. };
        root.left .= child;          // child 到下一个右花括号结束
    }
}
demo.k:7: error: storing a reference rooted at child, which does not outlive the destination (§9.2)

没有生命周期语法、没有借用规则，也没有 unsafe。编译器会自动推导每个引用的根源所在，一旦引用可能比宿主活得更久就直接拒绝编译。多个引用同时指向同一对象则完全允许。

C / C++
这段代码能够编译通过，而一旦持有 child 的作用域结束，root.left 就会变成悬垂指针。
Rust
同样会被拒绝，但持有引用的结构体必须写上生命周期参数（例如 struct Node<'a>），而且所有包含它的类型也得跟着标。

杜绝空指针解引用

struct Node { key: i32, left: Node? }

fn main() {
    var a = Node { key: 1, .. };
    let n = a.left;                   // Node? 可能为空
    if n { print(n.key); }            // 在 if 内部，n 是 Node&
    print(n.key);                     // 在外部，n 尚未经过检查
}
null.k:7: error: optional value must be narrowed (if/guard/assert) before use

除非类型明确声明，否则引用永远不为空。Node? 在使用前必须先经由 if、guard 或 assert 收窄检查，而在检查分支内部它就是普通引用。未经检查直接使用会报编译错误，因此运行时不存在可解引用的空指针。

C / C++
任何指针都可能为空，解引用空指针属于未定义行为，通常会直接崩溃。
Rust
Option<&T> 思路相同，需要通过 match、if let 或 unwrap() 解包。

整数行为完全忠于源码

fn main() {
    let a: u8 = 200;
    let b: u8 = 100;
    print(a + b);                 // 8 位加法：回绕为 44
    print(-7 % 3);                // % 为欧几里得取模：2
    var big: i32 = 2147483647;
    big += 1;                     // 有符号溢出
    print(big);
}

klang runtime error: integer overflow (debug): 2147483647 + 1 at i32 (ints.k:7)

算术运算按操作数自身的位宽执行，因此 u8 + u8 就是 8 位加法。较窄的类型可以自动拓宽，不用 as 就绝不会缩窄，而混用 u32 与 i32 会直接报编译错误，直到你明确写出要转成哪一种。无符号运算按定义回绕；有符号溢出在调试构建中中止、在发布构建中回绕，永远不会成为未定义行为。% 采用欧几里得取模，因此 x % n 永远是长度为 n 的数组的有效索引，而除以零总是中止运行。

fn main() {
    let x: u32 = 1;
    let y: i32 = 2;
    print(x + y);
}
mixed.k:4: error: operands of + have no common type: u32 and i32 (convert one with `as`)
C / C++
有符号溢出是未定义行为，优化器会假定它永远不会发生。uint8_t 的 200 + 100 会被提升为 int 的 300，有符号与无符号混算会静默转换，而 -7 % 3 等于 -1。
Rust
溢出在调试构建下 panic、在发布构建下回绕。类型不会自动拓宽，且 -7 % 3 等于 -1，需调用 rem_euclid 才得 2。

链接是节点所在数组内部 4 字节的偏移量，0 表示 null。整棵树里没有任何绝对地址，因此保存只需直接写出字节，加载时则会在使用前校验每一条链接。

C++
使用 unique_ptr<Node> 的节点本身占 24 字节，且每个节点还要外加一次堆分配和分配器头部开销。
Rust
Box<Node> 同样是 24 字节加一次分配。使用索引 arena 也能做到 4 字节链接，但它们没有类型约束，槽位复用时还会悄无声息地失效。

Rust

bench/results.md

速度从何而来

教程 §17

K 会编译成 C，因此 C 程序员手工也能写出这些布局。区别在于 K 把这些紧凑布局设为默认选择，并由编译器校验安全。即便面对已经使用 arena 和平坦偏移的 C++，K 仍保持 1.26× 的领先。

增长只是指针递增

没有 malloc、没有容量检查，也没有增长时的搬迁拷贝，因此指向增长中数组的引用始终有效。

释放只需一次写入

作用域结束时不运行任何析构函数。无论结构里有多少节点，只需把栈顶指针退回原位。

记录是一整块连续内存

字符串、列表和记录全部内联嵌套，中间没有指针跳转，扫描时直接顺序流过内存。

值直接在落脚处构造

无论调用栈有多深，值都直接在最终目标位置构造，因此按值返回一个可增长数组没有任何拷贝开销。

枚举只占各自实际内容的大小

叶节点和分支节点各自只占自身所需大小，case 函数则根据标签字节通过跳转表分发。

1、2 或 4 字节的链接

相对引用将带类型的链接存成小偏移量而非 8 字节指针，让更多结构能塞进缓存。

由编译器证明消去边界检查

每次索引访问都会做边界检查，除非编译器能证明其安全。像 u32 in dist 这样的索引类型只在存入时校验一次，而 checkfree 会拒绝仍残留边界检查的循环。

直接调用，按需内联

函数值仅存在于编译期，因此每一次调用都是直接调用，高阶代码也会直接编译成它看起来的那样循环。inline fn 会无视体积在每处调用点强制内联，并在 K 自己无法展开时请求 C 编译器内联。simd fn 则会额外生成 AVX2 和 AVX-512 版本，并在运行时选用 CPU 支持的最宽版本。

let evens = xs.filter() { it % 2 == 0 };     // 单个循环，直接写入 evens
inline fn lerp(a: f64, b: f64, t: f64) -> f64 { a + (b - a) * t }
simd fn encode(out: u8[>..]&, src: u8[:]) { ... }
C / C++
inline 主要控制链接属性。要强制内联得用 __forceinline 或 always_inline（各编译器写法不同），而且 std::function 与虚函数调用依然是间接调用。
Rust
#[inline(always)] 最为接近。作为泛型传入的闭包也能以同样方式内联，但 Box<dyn Fn> 仍是间接调用。

开箱即得的特性

教程 §12 至 §16

可跨层返回的错误

guard ok else { return [], str("bad age: ", line) from load; }

无论嵌套多少层调用，都能直接从 load 返回。编译器会检查每一处用法，因此无需栈展开器、无需异常机制，也无需 Result 类型。

C++
异常需要栈展开器与展开表，且任何调用都可能抛出异常。
Rust
需要靠 Result 沿着中间每一层调用用 ? 逐级向上传递。

互不共享的线程

thread_fn worker() {
    let job = qget<Job>();      // 在 Job 队列上阻塞等待
}

每个工作线程都会被编译成一个独立的小程序，拥有各自的内存空间。值通过带类型的队列以 memcpy 传递，因此根本不存在数据竞争、锁与原子操作。即便某个受控工作线程中止，也只会独自退出，主程序照常运行。

C++
线程共享内存，因此正确性完全依赖于锁、原子操作与内存序。
Rust
通过 Send、Sync 与 Mutex 检查共享安全性，但本质上仍是共享内存。

用于非嵌套生命周期的内存池

reusable var pool: Item[>..] = [];
let s0 = pool.alloc_index(Item { 10, 1.0 });
pool.free(s0);                                  // 槽位进入空闲链表
let s1 = pool.alloc_index(Item { 11, 2.0 });    // 随后被再次分配出去

缓存、图结构以及任何按任意顺序删除的对象，都可以存放在可复用内存池中，由池负责分发与回收槽位。陈旧的槽位句柄最多只会读到同一类型的另一个有效值，绝不会读到已释放的内存。

C / C++
指向已回收槽位的陈旧指针属于未定义行为，可能读到其他类型的数据或已释放内存。
Rust
slotmap crate 通过代数计数器捕获陈旧键；K 则将这部分交由你自行决定。

保存即写入字节

var image: u8[>..] = tree.to_bytes();
var loaded, ok = from_bytes<Node[>..]>(image);   // 先校验每一条链接

由相对引用链接起来的结构在任何内存地址下含义都完全一致。保存时直接写出它的字节即可，加载时则会逐一校验每个标签、长度与链接，因此损坏的文件只会得到 false，绝不会产生野引用。

C++ · Rust
指针写到磁盘上毫无意义，因此数据必须经过 protobuf、serde 等序列化器，或使用不安全的类型强转。

按字段或变体生成代码

fn visit_fields<T, F>(value: T&) {
    const for <N, A> in fields<T> { F(N, &value.A); }
}

const for 会在编译期为结构体的每个字段、枚举的每个变体或列出的每个类型重复生成代码。序列化器与访问器无需任何运行时反射。

Rust
由派生宏实现同样的功能，需要单独编写过程宏 crate。
C++
通常依赖宏或手写访问器。

纯正的 C 进，纯正的 C 出

// 从 K 调用 C
extern fn hypot(x: f64, y: f64) -> f64;
// 从 C 调用 K
export "c_add" fn add(a: i32, b: i32) -> i32 { a + b }

整个程序会编译成单个 C 文件，并直接调用 C 函数。export fn 则反过来让 K 可以作为库嵌入 C 或 C++ 程序。内置的 TinyCC 还能免去构建步骤直接在进程内运行程序。

C++
双向都使用 extern "C"。
Rust
调用 C 需要 unsafe extern 块，导出则需同时标注 no_mangle 与 extern "C"。

它对你的要求

教程 §18

由你决定数据住在哪里

通常谁构建值，就由谁拥有它。当生命周期不再呈现嵌套关系时，改用可复用内存池。

递归需将存储作为参数传入

递归函数无法跨递归调用保留可增长数据，因此需要把内存池或构建器作为参数传进去。

变长元素需遍历而非索引

变长记录数组是顺序存储的，除非你在旁边额外维护一张引用索引。

没有可逃逸的闭包或函数指针

函数值只存在于编译期，多态分发依靠枚举标签，整个程序须一次性全量编译。

已释放的池槽位可能变陈旧

归还某个槽位后若仍继续引用，只会读到后来复用它的新值。这是需要避免的逻辑错误，但绝不会导致内存破坏。

语言仍很年轻

语言规范仍处于草稿阶段，几乎每周都在演进。预编译发行版自 2026 年 10 月起开始发布。
